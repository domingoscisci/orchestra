# Manage OpenCode Child Sessions

This runbook covers creating, messaging, verifying, and deleting a child
session through the Orchestra plugin or OpenCode v2 API.

## Use the Orchestra plugin

The local `.opencode/plugins/orchestra.ts` entry point loads the implementation
from `src/index.ts`. It provides four tools under the `orchestra` namespace:

- `orchestra.create_agent`: create and prompt a child agent; returns its
  session ID.
- `orchestra.send_message`: message `parent` or a direct child by name or
  session ID.
  The sender is inferred from the calling session; message text uses a role
  icon and title, not the session ID.
- `orchestra.inspect_agent`: list direct children, or inspect one child and
  its status and recent messages.
- `orchestra.delete_agent`: delete one direct child and its descendants.

The plugin uses the calling session as the parent. Session IDs are generated by
OpenCode unless an explicit ID is supplied. The same API validation applies to
custom IDs.

## Prerequisites

- Run commands from the target project directory.
- Use the `opencode api` command so requests use the configured OpenCode
  service and authentication context.
- Set `<PARENT_ID>` to the ID of the parent session.

## Create a child session

Create the child with a custom ID, title, agent, and model:

> **OpenChamber tools note:** `session.create` does not expose `parentID` or a
> caller-supplied session ID. `session.fork` creates a fork, not a child created
> with the requested ID. To create a true child with a chosen ID, use the
> OpenCode API command below; OpenChamber tools can still inspect and message
> sessions.

```bash
rtk opencode api post /api/session --data '{
  "id": "ses_developer",
  "parentID": "<PARENT_ID>",
  "title": "Developer",
  "agent": "build",
  "model": {"providerID": "openai", "id": "gpt-5.6-luna"}
}'
```

The response should include the requested `id`, matching `parentID`, title,
agent, and model. The child starts without messages.

## Communicate in both directions

### Parent to child

Send a prompt to the child session:

```bash
rtk opencode api post /api/session/<CHILD_ID>/prompt \
  --data '{"text":"Reply only: OK"}'
```

The endpoint may return before the assistant finishes. Read the session
messages to verify the response:

```bash
rtk opencode api get /api/session/<CHILD_ID>/message
```

Check the result for an assistant message with the expected text and a
completed outcome.

### Child to parent

The parent-child link does not itself forward the child's final answer. Include
the parent session ID and the return instructions in the child's prompt. After
finishing its task, the child can post a message to the parent session:

```bash
rtk opencode api post /api/session/<PARENT_ID>/prompt \
  --data '{"text":"Developer: the task is complete."}'
```

For example, to ask the child to report only after a command succeeds, send a
prompt like this to the child:

```text
Run `sleep 300s` in your session. After it exits successfully, send
the message `Developer: sleep 300s completed.` to the parent session
<PARENT_ID> using the OpenCode API command below. Do not send the report
before the command succeeds.
```

```bash
rtk opencode api post /api/session/<PARENT_ID>/prompt \
  --data '{"text":"Developer: sleep 300s completed."}'
```

This posts a normal prompt to the parent session; include the child's name in
the text so the sender is identifiable. The parent does not need to poll the
child transcript for this message.

## Delete a child session

Delete the specific child by its ID:

```bash
rtk opencode api delete /api/session/<CHILD_ID>
```

Deleting a session also deletes its descendants. Do not substitute the parent
ID when the intent is to remove only one child.

To list a parent's direct children before deletion:

```bash
rtk opencode api get '/api/session?parentID=<PARENT_ID>'
```

The API does not provide a single operation to delete only all direct children
while preserving their parent; list the children and delete each child ID
individually.
